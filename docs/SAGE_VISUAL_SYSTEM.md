# SAGE ONE Visual System Reference

Status: approved visual direction for future app implementation.

## Source references

The visual references supplied in the SAGE ONE design conversation are references for **look, motion language, hierarchy, and atmosphere only**. They are not the source of truth for product behavior or system features.

The written SAGE ONE product/system specification remains the source of truth for behavior, permissions, learning, Evolution, memory, and platform capabilities.

## Brand identity

- Canonical SAGE ONE logo: the supplied SAGE mark with the metallic/glass S form.
- SAGE ONE should feel premium, futuristic, calm, intelligent, and highly usable.
- Avoid cheap-looking neon aesthetics.
- Use restrained light, reflections, particles, and glow rather than excessive neon.
- Backgrounds should be primarily plain/deep black.
- Typography should have an extremely subtle glow only where useful; readability always wins.
- The interface should feel expensive through spacing, materials, motion, hierarchy, and restraint rather than excessive effects.

## SAGE Core visual language

The SAGE logo/core is the main visual status element.

Use controlled state styling:

- Neutral / idle: restrained blue-white treatment.
- Research / active intelligence: blue.
- Analysis / processing: purple.
- Verification / connection: cyan.
- Recovery: purple through light sky blue into stable state.
- Success: green.
- Earning / achievement: gold.
- Failure / interruption: red/orange.

These colors are visual language, not a replacement for textual status or accessible UI indicators.

## Evolution visual behavior

Evolution rank should change the **SAGE Core/logo treatment, voice-interface visualizer, particles/spark effects, and related accent elements**.

Do not recolor the entire application into a loud themed background.

The background remains black and the UI remains restrained. Rank-specific identity appears primarily through:

1. SAGE Core/logo energy and material treatment.
2. Voice interface waveform/visualizer.
3. Spark/particle effects.
4. Small accent details and progress indicators.
5. Carefully controlled highlights.

Examples:

- Ruby: restrained ruby/crimson energy.
- Sapphire: sapphire-blue energy.
- Emerald: emerald-green energy.
- Gold: warm gold energy.

Every rank must remain recognizable as SAGE ONE while visibly evolving with the user's rank.

## Motion language

Motion should communicate meaning:

- Recognition: subtle activation.
- Processing: controlled orbital/energy movement.
- Verification: precise confirmation motion.
- Success: restrained positive release.
- Recovery: visible rebuild/reconnect/stabilize sequence.
- Earnings: stronger gold transformation appropriate to the event size.

Animations should be short, smooth, premium, and interruptible. Avoid constant motion that distracts from tasks.

## Research UI visual principles

Research should make source provenance visible without turning the screen into a cluttered dashboard.

When appropriate, show source identity, source count, verification state, and concise source details. The existing Research OS data model remains authoritative for actual sources, evidence, claims, verification, and citations.

## App information architecture / discovery

The app should make major areas discoverable with minimal effort. Use a dedicated **Marketplace / Opportunities** area or app box for categories such as:

- Buy / Sell / Marketplace
- Vacancies / Jobs
- Rent
- Land / Property
- Relevant categories and subcategories

The exact feature behavior and data model must follow the SAGE ONE product specification; this document defines only the intended visual organization and discoverability principle.

The marketplace area should be visually separate from core SAGE chat/research controls while remaining easy to reach.

## Usability rules

- Black is the visual foundation.
- High contrast and readable typography take priority over glow.
- Use subtle borders, depth, glass/material cues, and restrained highlights.
- Avoid visual overload.
- Major actions should be obvious without explanation.
- Navigation should remain consistent across screens.
- Status must never depend on color alone.
- Premium appearance must not reduce usability or performance.
- Heavy effects should be optimized for mobile hardware.

## SAGE Spark

The approved name for the SAGE internal credit concept is **SAGE Spark**.

The visual references may inspire its presentation, but this document does not define its economic rules. Those rules remain governed by the SAGE ONE written system specification.

## Design principle

> SAGE should evolve visually with the user, remain unmistakably SAGE, and become more sophisticated through restraint rather than more neon.
